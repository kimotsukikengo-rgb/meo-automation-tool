# Googleビジネスプロフィール連携 かんたんマニュアル

このツールと「Googleビジネスプロフィール（GBP）」をつなぐと、次のことが**自動**でできるようになります。

- 投稿文をそのまま**お店のGBPに公開**する
- お客様からの**口コミを取り込んで、返信文をつくって返す**
- 閲覧数・電話数などの**数字を自動で集めてレポートにする**

> このマニュアルは **パソコンが特別得意でない方でも読める** ように書いています。
> むずかしい準備（初回の1回だけ）と、ふだんの操作（だれでもできる）を分けて説明します。

---

## まず知っておくこと：2つのモード

このツールには2つの動作モードがあります。設定画面の上の方に、いま**どちらのモードか**が表示されます。

| モード | どんな状態？ | できること |
|---|---|---|
| 🧪 **おためしモード** | Googleとまだ正式につないでいない初期状態 | サンプル店舗を使って、投稿・口コミ・レポートの**画面操作をひと通り体験**できる（実際のお店には反映されません） |
| 🔗 **本番モード** | 後述の「初回の準備」が完了した状態 | **実際のお店のGBP**に投稿・返信・数値取得ができる |

**おためしモードのまま、すべての機能を画面で試せます。** あわてて本番にする必要はありません。

| 役割 | やること | 専門知識 |
|---|---|---|

# 🙋 ふだんの使い方（だれでもできる）

準備が終わったら、お店をつなぐのは**3ステップ**だけです。

### ① 設定画面を開く

画面上のメニューから **「設定・連携」** を開きます。

### ②「Googleと連携」ボタンを押す

- **本番モード**のとき → Googleのログイン画面が開きます。**お店のGBPを管理しているGoogleアカウント**でログインし、「許可」を押してください。管理権限のあるお店が自動で取り込まれます。
- **おためしモード**のとき → サンプル店舗が1件追加されます（練習用）。

### ③ 連携できたか確認する

画面の「連携中の店舗」に、お店の名前が出ていれば完了です。
これで投稿・口コミ返信・レポートの各画面から、そのお店を選んで使えます。

> **やめたいとき**：各店舗の右にある「連携解除」を押すと、つながりを切れます。いつでも押し直せます。

# 🛠 初回の準備（準備担当が1回だけ）

> ここから先は専門用語が出てきます。**運用担当の方はここを飛ばして大丈夫**です。
> 準備担当が下記を終えると、運用担当はボタン操作だけで使えるようになります。

## なぜ「APIキーを画面に貼る」ではないの？

GBPとの連携は、よくある「APIキーを1つコピペする」方式では**ありません**。
お店のオーナーが「このツールに操作を許可します」と**承認する**しくみ（OAuth 2.0 といいます）を使います。
そのため、画面に秘密の文字列を貼る欄はなく、必要な情報は**環境変数**（プログラムに渡す設定の置き場）にまとめて登録します。

| 置き場所 | どこに登録する？ |
|---|---|
| 本番（Vercel上で動かす場合） | プロジェクト → **Settings → Environment Variables** |
| 自分のパソコンで動かす場合 | プロジェクト直下の **`.env.local`** ファイル（Gitには上がりません） |

## ⚠️ 大事な前提：Googleの審査に数日かかります（最初の関門）

- GBPと連携するには、Googleに**利用申請**をして承認をもらう必要があります。承認まで通常**3〜10営業日**かかります。
- 承認されるまでは、Googleからデータを1件も取得できません（割当=0のため）。
- 代理店として複数のお店を管理する用途は対象です。条件は *自社のGBPが60日以上アクティブ* と *事業用のWebサイトがあること* です。
- 試作・社内検証の段階なら、Googleの「同意画面」を **「テスト」** 状態にして、使うGoogleアカウントを **テストユーザー（最大100人）** に登録すれば、本格的なアプリ審査なしで動かせます。

> **承認待ちの間も困りません。** 下記の `GBP_LIVE` を `off`（初期値）にしておけば、おためしモードのまま全機能を確認できます。

## 準備の流れ（チェックリスト）

```
□ 1. Google Cloud にプロジェクトを作る
□ 2. GBP の API 群を有効化し、利用申請を出す（承認待ち：数日）
□ 3. 「OAuth同意画面」を設定（テスト状態＋テストユーザー登録）
□ 4. 「OAuthクライアント（ウェブアプリ）」を作り、ID とシークレットを受け取る
□ 5. データ保存用の Postgres データベースを用意する
□ 6. 受け取った値を環境変数に登録する
□ 7. GBP_LIVE を on にして再起動／再デプロイ
□ 8. ツールの設定画面から「Googleと連携」で承認 → 完了
```

## 詳しい手順

1. **Google Cloud のプロジェクトを作成**します（[console.cloud.google.com](https://console.cloud.google.com)）。
2. **GBP関連のAPIを有効化**し、**利用申請**を出します。承認されると割当が `0 → 300QPM` に変わります（これが承認の合図）。
3. **OAuth同意画面**を設定します。ユーザー種別＝**外部**、状態＝**テスト**、テストユーザーに自分たちのアカウントを追加、スコープに `business.manage` を指定。
4. **OAuthクライアント（種類＝ウェブアプリ）**を作成し、**クライアントID** と **シークレット** を受け取ります。「承認済みのリダイレクトURI」に、下表の `GBP_OAUTH_REDIRECT_URI` と同じ値を登録します。
5. **Postgres データベース**（Neon など）を Vercel Marketplace で用意し、接続文字列（`DATABASE_URL`）を受け取ります。連携の記録を保存する場所です。
6. 受け取った値を、下記の表にしたがって**環境変数に登録**します。
7. `GBP_LIVE` を `on` に変更し、アプリを**再起動／再デプロイ**します。
8. ツールの**設定画面 →「Googleと連携」**から、お店のオーナーアカウントで承認すれば連携完了です。

## 環境変数の一覧（それぞれ何者か）

`.env.local`（自分のPC用）または Vercel の Environment Variables に登録します。

```bash
# ── Googleから受け取る値 ──────────────────────
GBP_OAUTH_CLIENT_ID=        # OAuthクライアントの ID
GBP_OAUTH_CLIENT_SECRET=    # OAuthクライアントのシークレット（秘密）
# 連携後にGoogleが戻ってくる先のURL（Google Console側にも同じ値を登録）
GBP_OAUTH_REDIRECT_URI=http://localhost:3000/api/gbp/callback
#   ↑ 本番は https://<アプリ名>.vercel.app/api/gbp/callback にする

# ── 自分で生成する「鍵」 ──────────────────────
# 連携情報を暗号化して守るための鍵（32バイトを base64 で）
#   生成コマンド: node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
GBP_TOKEN_ENCRYPTION_KEY=
# なりすまし防止用の署名キー
#   生成コマンド: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
GBP_STATE_SECRET=

# ── データベース ─────────────────────────────
DATABASE_URL=               # Postgres の接続文字列（Vercel Marketplace で発行）

# ── 動作モードの切り替え ─────────────────────
# off（または未設定）= おためしモード / on = 本番モード
GBP_LIVE=off
```

| 変数名 | これは何？ | だれが用意する？ |
|---|---|---|
| `GBP_OAUTH_CLIENT_ID` | アプリの公開ID | Google Console |
| `GBP_OAUTH_CLIENT_SECRET` | アプリの秘密の合言葉 | Google Console |
| `GBP_OAUTH_REDIRECT_URI` | 連携後の戻り先URL | 自分で決めて両方に登録 |
| `GBP_TOKEN_ENCRYPTION_KEY` | 連携情報を暗号化する鍵 | 生成コマンドで作成 |
| `GBP_STATE_SECRET` | なりすまし防止の署名キー | 生成コマンドで作成 |
| `DATABASE_URL` | 連携記録の保存先 | Vercel Marketplace |
| `GBP_LIVE` | おためし/本番の切替 | `off` か `on` を入れるだけ |

# 困ったときは（よくある質問）

**Q. 「Googleと連携」を押してもサンプル店舗しか出ません。**
A. まだ**おためしモード**です。本番にするには、準備担当による「初回の準備」が必要です。

**Q. エラーが画面に出ました。**
A. 設定画面にはわかりやすいメッセージが出ます。代表的なものは下記の通りです。

| 画面のメッセージ | 意味・対処 |
|---|---|
| 連携の検証に失敗しました（state 不一致） | 時間が空いた可能性。**もう一度**「Googleと連携」を押してください。 |
| リフレッシュトークンが取得できませんでした | Googleアカウント側の連携（権限）を**一度解除**してから、もう一度お試しください。 |
| OAuth設定が不正です | 準備担当へ：環境変数（ID/シークレット/リダイレクトURI）を確認してください。 |
| Google側で連携が拒否されました | 承認画面で「許可」ではなく「キャンセル」した可能性。もう一度お試しください。 |

**Q. データはどこに保存されますか？**
A. 「保存先：Postgres」と表示されていれば、データベースに安全に保存されます。「メモリ（揮発）」と出ている場合は、アプリ再起動で消える一時保存です（`DATABASE_URL` 未設定）。

**Q. 秘密の情報はどこにありますか？**
A. すべて**環境変数**にあり、画面やコードには出てきません。漏れた疑いがあれば、その値を作り直して（ローテーション）登録し直してください。
